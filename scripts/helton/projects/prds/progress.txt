## Codebase Patterns
- `make ready` (lint+typecheck+test) roda da raiz e leva ~4 min; termina com "==> make ready verde: pode commitar".
- `ruff format` (dentro do `make lint`) reformata o que você acabou de escrever — rode `make ready` antes de conferir o diff final.
- Teste com `@pytest.mark.django_db` NÃO parte de banco vazio: a data migration `programs/0002` semeia o programa PPGD e os Groups de papel. Asserção de queryset global precisa filtrar pelos objetos criados no próprio teste.
- Migration de data segue o padrão de `programs/0002`: funções `criar`/`desfazer` em português, `apps.get_model`, e `RunPython(criar, desfazer)`.
- QuerySet customizado por model (`ProgramQuerySet.as_manager()`); query nova entra como método nomeado no `models.py` (Seção 8 do CLAUDE.md), nunca solta no router.
- Ambiente deste canteiro: nginx em http://localhost:8330, Postgres do host em 5683 (ver `.env`). Não use a 8080 do checkout principal.
- `make seed` do host não funciona no canteiro: `docker compose exec -T backend uv run python manage.py seed_demo --force` (com `uv run`, sempre).
- `save(update_fields=[...])` precisa citar `updated_at`: o `auto_now` só é gravado para os campos listados.
- Service novo se exercita no canteiro sem sujar dado: `manage.py shell -c` com `transaction.atomic()` e um `raise` no fim para dar rollback.

## 2026-09-03 - f5-fila-router
- Três rotas no `access_router` (`apps/academic/router.py`, fim do arquivo):
  `GET /api/v1/access/requests/` (`view_accessrequest`, `@paginate`,
  `for_program(current_program)` + `select_related("person")`, filtro de `status`
  com **default `pending`** — a fila existe para o que falta decidir, e as outras
  duas situações são o histórico que a tela pede), `POST .../{id}/approve` e
  `POST .../{id}/reject` (ambas `change_accessrequest`). Ordem sempre
  `require_perm` → `current_program`.
- `_cadastro_para_decidir(...)` — espelho de `_requerimento_para_decidir`, com
  `raise NotAllowed("Ninguém confirma o próprio cadastro.")`. **O nome NÃO é
  `_solicitacao_para_decidir`**: esse já existe no mesmo arquivo (`:545`) para
  `EnrollmentAdjustmentRequest`, e o `mypy` pegou o `no-redef` — mas só depois de
  três erros em cascata que apontavam para o helper errado.
- O router resolve `project`/`advisor` com os `_projeto`/`_orientador` já
  existentes, escopados em `for_program(program)`: id de outro tenant vira 404 na
  borda, não `IntegrityError` no service.
- Schemas em `apps/academic/schemas.py`: `AccessRequestOut` (o **declarado** —
  categoria, titulação, instituição, Lattes — mais nome/e-mail/telefone da pessoa
  resolvidos, para a fila não fazer uma consulta por linha), `AccessApproveIn`
  (todos os campos opcionais na borda de propósito: o que cada perfil exige
  depende do `profile` que está no banco, e quem cobra é o domínio) e
  `AccessRejectIn { note }`.
- `make ready` verde: 1973 passed, 10 skipped em 184s. Exercitado no canteiro com
  `manage.py shell` + `transaction.atomic()` e rollback: fila lista só a pendente
  do programa; `?status=approved` vazio; `?status=banana` 422; aprovar criou o
  `Teacher` e deixou a conta só em `['Docente']`; aprovar de novo 409
  `already_decided`; recusar em branco 400 `rejection_requires_note`; recusar com
  motivo arquivou a `Person`; Discente 403; id inexistente 404; secretária

- Arquivos: backend/apps/academic/router.py, backend/apps/academic/schemas.py
- **Learnings for future iterations:**
  - **`apps/academic/router.py` tem 1600+ linhas e nomes de helper se repetem por
    domínio.** Antes de criar `_algo_para_decidir`/`_meu_algo`, rode
    `grep -n "^def _" apps/academic/router.py` — o `mypy` avisa, mas com erro de
    tipo em cascata que aponta para a assinatura do homônimo, não para a colisão.
  - Rota de fila com filtro de enum e default: `status: AccessRequestStatus =
    AccessRequestStatus.PENDING` (sem `| None`). Não existe "ver tudo", e é
    intencional — o `| None` que os outros filtros usam é para conveniência, não
    para fila de trabalho.
  - `AccessRequestOut` **não** carrega `*_label`, ao contrário de
    `AccessStatusOut`: a fila é lida por quem tem permissão e vai usar o
    `lib/acesso.ts` da f6. Só a tela de espera precisa dos rótulos prontos,
    porque quem a lê não tem permissão para mais nada.
  - O service `approve_access_request` MUTA a instância recebida (`approve()` no
    mesmo objeto), então a rota devolve `solicitacao` direto — sem `refresh_from_db`.
