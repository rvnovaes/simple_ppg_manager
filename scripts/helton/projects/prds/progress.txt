## Codebase Patterns
- `make ready` (lint+typecheck+test) roda da raiz e leva ~4 min; termina com "==> make ready verde: pode commitar".
- `ruff format` (dentro do `make lint`) reformata o que você acabou de escrever — rode `make ready` antes de conferir o diff final.
- Teste com `@pytest.mark.django_db` NÃO parte de banco vazio: a data migration `programs/0002` semeia o programa PPGD e os Groups de papel. Asserção de queryset global precisa filtrar pelos objetos criados no próprio teste.
- Migration de data segue o padrão de `programs/0002`: funções `criar`/`desfazer` em português, `apps.get_model`, e `RunPython(criar, desfazer)`.
- QuerySet customizado por model (`ProgramQuerySet.as_manager()`); query nova entra como método nomeado no `models.py` (Seção 8 do CLAUDE.md), nunca solta no router.
- Ambiente deste canteiro: nginx em http://localhost:8330, Postgres do host em 5683 (ver `.env`). Não use a 8080 do checkout principal.
- `make seed` do host não funciona no canteiro: `docker compose exec -T backend uv run python manage.py seed_demo --force` (com `uv run`, sempre).
- Rota do backend aposentada só quebra o front quando alguém roda `make gen-api`: o
  `schema.d.ts` é versionado. Removeu endpoint, `grep -rn "'/rota/antiga'" frontend/src`.
- Path no client tipado vai SEM o prefixo `/api/v1` (o `scripts/normalizar-openapi.mjs`
  o remove antes do `openapi-typescript`).
- `save(update_fields=[...])` precisa citar `updated_at`: o `auto_now` só é gravado para os campos listados.
- Atributo abreviado do Svelte em template (`<option {value}>`) reprova no `eslint` do
  projeto com `'value' is not defined  no-undef`; escreva `value={valor}` por extenso.
- Rótulo de enum do domínio mora em `frontend/src/lib/<assunto>.ts` (`isolada.ts`,
  `acesso.ts`), com um `ROTULO_DO_*` e a `ORDEM_*` correspondente — nunca inline na tela.
- `eslint-disable-next-line svelte/no-navigation-without-resolve` NÃO cobre `<a>` que o
  prettier quebra em várias linhas; use o par `eslint-disable`/`eslint-enable` em volta
  do elemento (padrão de `(app)/analise`).
- Rota nova gera artefato root em `.svelte-kit/types/` E em `.svelte-kit/generated/`;
  apague os DOIS de dentro do container quando o `make typecheck` der EACCES.
- Service novo se exercita no canteiro sem sujar dado: `manage.py shell -c` com `transaction.atomic()` e um `raise` no fim para dar rollback.

- **Learnings for future iterations:**
  - **`<!-- eslint-disable-next-line svelte/no-navigation-without-resolve -->` não cobre
    `<a>` multilinha**: o prettier quebra o elemento e o `href` cai duas ou três linhas
    abaixo do comentário, então a regra reprova mesmo assim. Use o par
    `<!-- eslint-disable ... -->` / `<!-- eslint-enable ... -->` em volta do elemento,
    que é o padrão já usado em `(app)/analise`.
  - A armadilha 6 (EACCES no `.svelte-kit`) apareceu inteira: a rota nova fez o Vite do
    container gerar `types/src/routes/(app)/solicitacoes/` **e**
    `generated/client/nodes/NN.js` como root. Apagar SÓ o diretório de types não basta —
    o `generated/` também precisa ir:
    `docker compose exec -T frontend sh -c 'rm -rf "/app/.svelte-kit/types/src/routes/(app)/<rota>" /app/.svelte-kit/generated'`.
  - Rota nova em SPA com Vite dev no Compose **não pede rebuild do front**: o serviço
